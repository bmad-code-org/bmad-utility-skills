# Twitter/X Posts

Generate a **series of standalone tweets** designed to be scheduled and spaced out over days. Each tweet must work on its own as an exciting announcement, not depend on the others.

**Tweet 1 — Release Announcement (flagship):** The main "we just released vX.Y.Z" tweet. High energy, top 2–3 highlights, install command, link to repo. Goes out on release day.

**Tweets 2–N — Feature/Fix Spotlights:** One tweet per noteworthy feature, improvement, or bug fix. Each should:
- Open with a hook (question, bold claim, or pain point solved).
- Describe the single feature/fix and why it matters.
- End with a CTA (try it, star the repo, check the docs).
- Include relevant hashtags.

## Guidelines

- Target **280 characters or fewer** per tweet (X free tier limit) so posts work for any account tier.
- Generate **3–8 tweets** depending on how much is in the changelog.
- Order by impact/excitement so the best content posts first.
- Each tweet feels like its own mini-announcement, not a fragment.
- Include a suggested posting schedule (e.g. "Day 1", "Day 2", "Day 3") to space them out.

## Links & follow (length-aware)

- **One link per tweet, max** — the 280-char limit means you can't stack a footer of links on every tweet.
- The flagship tweet carries the primary CTA link (the install/repo, or `bmadcode.com`).
- Add a short **closing "where to find us" tweet** pointing to the site and socials, listed compactly to fit 280 chars, e.g.:
  `More from BMad → site: bmadcode.com · YouTube: @BMadCode · FB: facebook.com/@BMadCode`
- Don't repeat the same link across tweets; vary which channel each spotlight tweet points to.
